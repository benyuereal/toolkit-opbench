# 任务：mHC 后处理这一段，还能压出多少带宽

## 背景

我们在 8 卡 DCU（gfx938，Hygon BW1100）上跑 GLM-5.3-Flash。模型用了 mHC
（hyper-connection）：残差流不是一条，而是 **hc = 4 条并行**，层与层之间靠一组
学出来的混合系数把它们重新组合。

每层的 mHC 分两段，本题是**后一段**（`hc_post`）：上一层已经算好了 4 份候选
输出，这一段把它们混合成新的 4 份残差，交给下一层。

```
out[m, i, h] = post[m, i] * x[m, h]  +  Σ_{j=0}^{3} comb[m, i*4+j] * residual[m, j, h]
```

右边第一项：本层输出 `x`（只有 1 份）按 4 个不同的标量各缩一次。
第二项：上一层的 4 份残差按一个 4×4 矩阵混合。

它夹在每个 attention/FFN 的出口，每层都跑一次。**没有矩阵乘**——那个 4×4 的
混合矩阵是逐 token、逐位置的，H 方向 4096 个位置各算各的。

## 算子定义

```
输入
  x         [M, H]        bfloat16   本层输出
  residual  [M, HC, H]    bfloat16   上一层留下的 HC 份残差
  post      [M, HC]       float32    第一项的缩放系数
  comb      [M, HC*HC]    float32    4x4 混合矩阵，行主序 comb[m, i*HC+j]

输出
  out       [M, HC, H]    bfloat16

  H = 4096, HC = 4 固定
```

`M` 是变量（token 数），会出现多个档位。

`comb` 的行和约为 1（它是 Sinkhorn 迭代的输出，非负），`post` 非负。
两者在真实模型里都不会出现负值。

## 正确性判定（硬门槛）

**输入输出对得上就算正确，不管用什么实现。**

- 判据是**相对 L2 误差** + 逐元素绝对上界，不是逐元素相对误差。
  原因：bf16 下 5 项相加会出现**抵消**——某一支的和恰好接近 0 时，绝对误差
  很小但相对误差会爆表。逐元素相对误差在这种元素上永远不可能过，
  那是判据不适配，不是实现错。
- 累加精度：参考实现用 fp32 中间量。bf16 直接累加会有几 ULP 的差异，属正常。
- `out` 的形状、dtype 必须与上表一致。

## 要回答的

**在本机跑这一段，带宽达成率是多少？还有多少空间？**

具体要给出：

1. **落到了哪个实现**：`库.函数`、版本、**完整调用签名**
2. **实测耗时**：题面给出的每个 M 档都要有数字
3. **有效流量**：这一段实际读写多少字节，怎么算的
4. **达成率**：分母取自哪里、为什么可信
5. **结论**：还有多少空间、下一步该动哪里（或者"已经到顶，别动"）
6. **复跑**：给出命令与脚本位置
