# 参考答案（不给 agent 看）

## 当前已知结论（截至 2026-11-23）

**没有可直接调用的独立 symbol。** hadamard 变换**内联**在 MHC 的融合 kernel 里
（`mhc_pre_mix_kernel` 一类），不作为独立函数导出。

三种情况要分清（本题的核心）：
1. 库 import 不到 → 错，库在
2. `dir(lib)` 里没有 `hadamard` / `walsh` 之类 → 这一步通常能查到
3. **有**类似名字但它是**内联在别的 kernel 的源码里**，不是可调用入口 → 正确答案

## 合格的回答长什么样

- 遍历了相关库的符号（`dir()`、源码 grep、`.so` 的 nm/strings），贴出输出
- 明确结论「没有独立 symbol」
- 指出它**在哪**（内联在某个融合 kernel 里），而不是停在"没有"
- 给出替代：要单独用 hadamard，只能自己写，或复用那个融合 kernel 的整体

## 不合格的回答

| 回答 | 判定 | 为什么 |
|---|---|---|
| 「有，调 `lightop.hadamard` 即可」 | **0 分 + 幻觉** | 编造了一个不存在的 symbol |
| 「没有」但不查它在哪 | 60 分 | 结论对，不完整 |
| 「大概有吧，需要再看」 | 20 分 | 诚实但不完整 |

## 一个必须允许的例外

如果 agent 真的找到了一个可调用的 symbol 并跑通（贴出 import 与输出），
以它为准。**这一类题最容易被我们自己的记录误导**，实测优先。
