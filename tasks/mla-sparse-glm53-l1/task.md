# 任务：GLM-5.3-Flash 形状的稀疏 MLA 前向——实现选型与达成率

## 背景

我们在 8 卡 DCU（gfx938，Hygon BW1100）上跑 GLM-5.3-Flash 的推理。它的注意力
是 **DSA（DeepSeek Sparse Attention）** 形态：每个 query 不再看全量 KV，而是先由
一个轻量 indexer 挑出 top-k 个历史 token，再只在这 top-k 个 token 上做 MLA。

本题要测的就是**挑完之后那一步**：给定 top-k 下标，做稀疏 MLA 前向。

这一段在真实模型里的参数量来自 GLM-5.3-Flash 的 `text_config`：

```
num_attention_heads = 64        kv_lora_rank     = 512
qk_nope_head_dim    = 256       v_head_dim       = 256
index_topk          = 2048      qk_rope_head_dim = 0
```

也就是说：**每个头参与打分的通道是 768 维，但输出只有 256 维**。这个
「宽进窄出」是本题与常见 DeepSeek 形状（576 进 / 512 出）最不一样的地方。

## 算子定义

```
score[i,h,j] = q[i,h,:] · kv[indices[i,0,j], :] * sm_scale      j ∈ [0, TOPK)
out[i,h,:]   = softmax_j(score[i,h,j]) · kv[indices[i,0,j], :DV]
```

| 张量 | 形状 | dtype |
|---|---|---|
| `q` | `[S, 64, 768]` | bfloat16 |
| `kv` | `[8192, 1, 768]` | bfloat16 |
| `indices` | `[S, 1, 2048]` | int32 |
| `out` | `[S, 64, 256]` | bfloat16 |

`sm_scale = 1 / sqrt(768)`。`kv` 在 64 个头上是**共享**的一份（MLA），
`indices` 里存的是 KV 缓冲区的行号。

`S` 是变量，会出现多个档位（decode 段的小 S 与 prefill 段的大 S）。

## 正确性判定（硬门槛）

**输入输出对得上就算正确，不管用什么实现。**

上面的公式是**算子语义**，用来对齐"这个算子在算什么"。
判定只看一件事：给定同样的输入，你的输出与参考实现在
**rtol = 0.05 / atol = 0.005** 内一致（bf16 精度下的合理容差）。

- 用哪个库、写 Triton、写 HIP、几段拼接——**都不限**。
- 中间怎么算、按什么顺序算、是否复用缓冲区——**都不限**。
- 满足上面容差、shape 对、dtype 对，正确性就通过。

输入由 harness 按固定 seed 生成，`q` / `kv` 是标准正态的 bf16，`indices` 是 int32。
**动手前先把自己的实现和参考语义在真实输入上对齐一遍，别只对着自造的数据验。**
