# 任务：repeat_kv 值不值得单独做一个算子

## 背景

我们在 8 卡 DCU（gfx938）上做 GQA 注意力的解码优化。GQA 里 KV 头数比 Q 头数少，
常见做法是把 KV 沿头维 `repeat` 到与 Q 头数一致（`repeat_kv`），再走标准 attention。

团队在整理算子清单时提出：既然 repeat_kv 在每层每个 step 都调用一次，
**是不是应该给它做一个专门优化的算子**（重写 kernel、减少拷贝、甚至和 attention 融合）？

## 要回答的

**应该为 repeat_kv 单独实现一个算子吗？为什么？**

要求给出：

1. **结论**：应该 / 不应该，以及理由
2. **依据**：你实际测了什么——纯 repeat 的耗时、内存占用、或者其它
3. **量级判断**：这一段的耗时相对整个 attention 是什么量级
4. **替代**：如果不单独做，正确做法是什么（能省掉这次拷贝吗？）
5. **复跑**：给出你跑的命令与脚本位置

## 约束

- 时间预算：**30 分钟**
- 只写你实际验证过的东西。**没验证的写「未验证」，不要推测成结论。**
- 产出写到当前目录的 `report.md`，验证脚本放 `scripts/`，原始输出放 `results/`。

## 评判标准

> 这道题考的是「该不该做」，不是「怎么做得更快」。
> 给出一个精心优化的 repeat_kv kernel 而没回答"该不该做"，视为答错方向。
