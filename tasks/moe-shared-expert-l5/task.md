# 任务：共享专家能否与路由专家并发执行

## 背景

我们在 8 卡 DCU（gfx938）上优化一个 MoE 层。这一层的结构是：

```
x → [路由专家 × E，每 token 取 top-k] → 加权求和 → +
x → [共享专家 × 1，所有 token 都走]    →            = y
```

共享专家和路由专家是**互不依赖**的两条分支。团队里有人看到这一点，提出：

> 把共享专家放到独立 CUDA/HIP stream 上，让它和路由专家**并发执行**，墙钟时间应该能省下共享专家那一段。

## 要回答的

**在本机，这个并发方案能不能真正省时间？给出重叠度的实测值。**

要求给出：

1. **结论**：能 / 不能 / 部分，以及重叠度是多少（给数字）
2. **依据**：你怎么测的（串行 vs 并行的对比方式、`torch.cuda.Event` 或其它）
3. **机制**：如果不能重叠，说清为什么——是引擎/队列、访存、还是别的资源
4. **复跑**：给出你跑的命令与脚本位置

## 约束

- 时间预算：**30 分钟**
- 只写你实际验证过的东西。**没验证的写「未验证」，不要推测成结论。**
- 两侧耗时量级差距过大时，重叠度会被噪声支配——这种情况要说明，不要硬给一个比例。
- 产出写到当前目录的 `report.md`，验证脚本放 `scripts/`，原始输出放 `results/`。

## 评判标准

> 正确答案不是「理论上可以并发」。
> 是「在这台机器上实测重叠了多少，为什么是这个数」。
> 只给架构层面的推理、拿不出实测重叠度的，视为依据不足。
