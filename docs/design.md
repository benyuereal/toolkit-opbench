# DCU 算子优化 skill 的能力评测设计

> 问题：**怎么证明「带 skill 的 agent」比「裸 Claude Code」更好？要不要打榜？我们不是 NVIDIA。**
> 结论先说：**不打外部榜，但要建内部记分板；核心实验是三臂对照，不是绝对分数。**

---

## 一、先把命题说清楚

我们要证明的不是「我们的 skill 很强」，而是：

> **在 DCU 上、同等预算下，带 skill 的 agent 比裸 Claude Code 产出更好的优化结论。**

这是一个**增益（uplift）**命题，不是绝对能力命题。推论：

- 不能报「我们做到 4.4×」这种绝对数——那是 CompoundingKernel 在 B200 上的成绩，与我们无关
- 唯一有意义的数是 **Δ(带 skill − 裸 CC)**，同题、同预算、配对比较
- 如果 Δ ≈ 0，那这套 skill 就不该继续投入。**这是必须允许出现的结论。**

---

## 二、为什么不能打外部榜（三条硬理由）

| 榜 | 生态 | 为什么不适用 |
|---|---|---|
| **SOL-ExecBench** | B200 / CUDA | SOL 时间按 NVIDIA 峰值算；题目是自包含算子，不涉及库选型 |
| **KernelBench / TritonBench** | A100/H100 / CUDA | 参考实现依赖 tcgen05 / TMA / wgmma，gfx938 没有 |
| **MLPerf** | 全栈 | 端到端系统级，需要合规提交与完整推理栈，成本远超我们 |

三条硬理由：

**① 分母不可迁移**
外部榜的 SOL 分是按 B200 峰值定的。我们的分母必须自己标定——而且刚在这上面栽了两次（540 无来源、49.8 当峰值）。用别人的分母等于把错误标准化。

**② 指令集不可迁移**
gfx938 没有 tcgen05 / TMA，`aiter.asm_fmoe_a8` 对所有 dtype 都拒（已实测），asm 只有预编译 .so。榜上的最优解大量依赖这些指令，我们一个也用不上。

**③ 题目不可迁移**
外部榜考「从零写 kernel」（他们中位 7000 行 CUDA）。我们考「选对库 + 改对地方」。**这是两种不同的能力，用前者的题测后者，结论无效。**

---

## 三、但「榜单的形式」要留：内部记分板

不打外部榜，但要有**内部记分板**，作用不是对外证明，是**防改坏**：

- 题集 + 评分脚本入库，任何人可复跑
- 每次改 skill 跑一遍，看分数有没有掉
- 我们已经有 5 道「结构门禁」（lint / sanitize / atlas / tests / eval），但**没有一道「能力门禁」**——这是缺口

一句话：**门禁管「东西没坏」，记分板管「本事没退」。**

---

## 四、题集：五层，其中一层是别人没有的

| 层 | 考什么 | 题源 | 判分方式 |
|---|---|---|---|
| **L1** 已覆盖算子 | 知识层的直接价值 | 46 张卡里的高频算子 | 能否落到 `import_path` 并跑出 ratio |
| **L2** 未覆盖算子 | 泛化 / 迁移 | 卡里没有的算子（**写卡期间冻结，不许提前看**） | 允许「查不到」，但要说清查了什么 |
| **L3** pipeline 段 | 边界判断 | MoE 五段、MLA 吸收/非吸收 | 是否给出**可执行的拐点或选择规则** |
| **L4** 端到端改造 | 工程闭环 | 真实仓库改一处（如 EP 的 combine） | 端到端指标 + 无回归 |
| **L5 反事实题** | **敢说「此路不通」** | 已知死路：asm 全拒、pack5 无公开入口、双流叠两段 GEMM | **答「不通 + 机制」得满分；答「能优化 X%」得 0 分** |

### L5 是 DCU 场景独有的、比速度更重要的一层

我们的最大风险不是「不够快」，是**「编一个看起来合理的结论」**。这两天已经出现三次：`in-house` 29 条、两个幽灵库（hipBLASLt / TileKernels）、49.8 当峰值。

**外部榜没有这一层，因为它假设题目一定有解。** 而我们的真实工作里，一大半时间在判断「这条路到底通不通」。

L5 也是**最便宜的题**——不用跑 bench，只要它判断对。信息量却最高。

## 五、三个臂：把「两层价值」拆开

这是整个设计的核心。

| 臂 | 给什么 | 目的 |
|---|---|---|
| **A 裸 CC** | 算子名 + shape + dtype + 预算 | 基线 |
| **B 库清单** | 加 `libraries-registry.yaml`（有哪些库、版本、是否安装），**不给任何判据** | 隔离「知道在哪」的价值 |
| **C 完整 skill** | 加 atlas + scenarios + failure modes + 判据 | 全量 |

**为什么必须三臂**：我们的 skill 其实有两层价值——

1. **知道在哪**（哪个库、哪个函数、什么版本）
2. **知道怎么判断**（什么场景用哪个、什么时候别用、哪条路会崩）

两臂只能证明「有用」，**三臂能证明「哪层有用」**。

如果 `B ≈ C`，说明值钱的只是库清单，**判据层是负担 → 该砍**。这个可能性不低，因为 CompoundingKernel 的负结果已经提示：把参考资料从可选改强制，没有可测量增益。

## 六、指标体系（七个，前三个是主指标）

| # | 指标 | 定义 | 为什么重要 |
|---|---|---|---|
| 1 | **有效结论率** | 产出带可复跑数字的结论 / 总题数 | 治「写了一堆但没有数」 |
| 2 | **正确率** | 编译过 + 数值对（含未提交 shape + stress 数值） | 治「快但算错」 |
| 3 | **几何平均加速比**（跨 shape） | 对基线的几何平均 | 治「挑一个好看的形状报数」 |
| 4 | **校准度** | \|宣称达成率 − 实测达成率\| ≤ 10pt | **治「到顶/有空间」判错**（49.8 那次的病） |
| 5 | **幻觉率** | 编造 `import_path` / 库名 / 数字 / 行号的比例 | 可机检：逐条 import + 文件存在性 |
| 6 | **评估吞吐** | 可靠测量次数 / 小时 | 这才是规模的真瓶颈 |
| 7 | **复用率** | 后续任务引用既往结论的次数 | **衡量复利——这是 skill 与裸 CC 最本质的差别** |

第 7 条最容易被忽略，但它才是「skill」这个词的意义：**如果每次任务都从零想，那就不叫 skill，叫 prompt。**

## 七、防作弊五条

1. **预算固定**：wall time + token 双限，超预算的产出不计分
2. **不接受自报数字**：评分器必须重跑；`results/` 缺文件直接判 0
3. **留出 shape**：评测 shape 与题面 shape 不完全一致（留 20%）
4. **L2 题冻结**：写卡期间不许看，写了就是泄题
5. **记录 `clock_mhz` + `timestamp`**：防止「时钟快的机器测出好数」（论文里他们 pod 时钟比站点快 1.19×）

---

## 八、统计：一台机器也能出结论

- **配对设计**：同题、同预算，三臂跑同一题
- **样本量**：每臂 8–10 题。我们只有一台机器，追求**可重复**而非大样本
- **检验**：Wilcoxon signed-rank 或符号检验，报 p 值 + 效应量
- **先定胜负规则再跑**：否则一定会挑结果讲故事

这点是受了论文的教训：现在 arXiv 上一批 self-improving 工作，涨 2.36 个点（p=0.003）都可能落在噪声区间。**配对 + 预注册胜负线，是唯一能自救的做法。**

---

## 九、成本现实

```
3 臂 × 10 题 × 30 分钟 = 15 小时
```

可行，但要按信息量排序：

1. **先跑 L5**（反事实题）——最便宜，不用 bench，且直接暴露幻觉
2. **再跑 L1**——知识层价值的直接检验
3. **最后 L3/L4**——贵，且需要真实仓库环境

夜间跑，白天评。GPU 空转时优先。

## 十、MVP：一周内能出结果的最小实验

| 题 | 层 | 为什么选它 |
|---|---|---|
| `gemm-bf16` | L1 | 有卡、有实测、分母已校准（310 TF） |
| `fused-add-rmsnorm` | L1 | 唯一九件套齐全的样板卡 |
| `rmsnorm` 的未见变体 | L2 | 测迁移，且不能提前写卡 |
| `asm_fmoe_a8` 可用性 | **L5** | 已知答案：全 dtype 拒。答「能融合」= 幻觉 |
| MoE 融合边界 | L3 | 已有 M*=32–64 的实测结论可对照 |

**3 臂 × 5 题 × 30 分钟 = 7.5 小时**，一晚跑完。

**决策规则（跑之前先定死）**：

```
C 相对 A 的有效结论率提升 < 20%  ⇒ 重估知识层价值，砍文档而不是加文档
B 与 C 差距 < 10%               ⇒ 判据层没价值，只保留库清单
C 的幻觉率 > A                  ⇒ 立刻停，说明 skill 在教模型编答案
```

## 十一、终局指标：人工盲评

所有机检指标都可以被优化，唯一不能作弊的是**人**：

> 把三臂产出的报告去掉来源标记，让做过 DCU 优化的工程师评「**这份结论能不能直接用于决策**」，以及「要返工几次」。

这是最贵、也最真的指标。建议放在 L4 端到端题上做，样本不用多，5 份就够看出差别。

---

## 十二、什么时候才需要对外证明

对外（论文 / PR / 客户）是第二阶段的事，需要：
- 开源一个「DCU 版 KernelBench 子集」（我们自己的题 + 我们自己的分母标定）
- 邀请第三方复跑
- 这才能叫「打榜」，而且是我们自己定义的榜

**第一阶段唯一目标：知道自己这套东西到底值不值。** 先别想榜。
