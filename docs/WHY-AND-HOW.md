# 怎么测「skill 有没有用」—— 设计与执行计划

> 上一轮的教训：**L1 题测不出 skill 的价值。**
> gemm / rmsnorm / gating 考的是「接口怎么调、达成率多少」，
> 裸 agent 自己 `dir()` + 试错就能做对。三臂必然同分，Δ≈0。
>
> 要测出增益，题必须落在**裸 agent 无法自己发现**的知识上。
> 下面按这个原则重排。

---

## 一、skill 里到底有什么是「探测不到」的

把 `toolkit_skills` 的知识按「裸 agent 能不能自己得到」分两类：

| 类型 | 例子 | 裸 agent 能否发现 | 数量 |
|---|---|---|---|
| **接口/性能事实** | `aiter.moe_c_topk_softmax` 的四个参数；gemm 307 TF | ✅ 能（试错 + 测量） | 大量 |
| **死路记录** | `asm_fmoe_a8` 的 mode 空间与 get_solutions 不对齐 | ❌ **不能** | 9 条 failure_modes |
| **被否证的方向** | 融合 `moe_sum` 进 epilogue 实测慢 2.5–3× | ❌ **不能** | 44 条 refuted |
| **分母口径** | 49.8 是 impl_measured 不是峰值 | ❌ **不能**（除非踩过） | ~6 处 conflicts |
| **测量纪律** | 不 flush L2 会量出 4571 GB/s | ❌ **不能** | 散落多处 |

**结论：L1 题是在测第一行，L5/L3 题才在测后四行。**

---

## 二、三层实验设计

### 第 1 层：L1 三臂对照（**已就绪，但预期 Δ≈0**）

目的不是证明 skill 有用，是**建立"裸 agent 的基线能力"**。

| 题 | 状态 | 预期 |
|---|---|---|
| `gemm-bf16-l1` | ✅ 六件套 + 基线 | 三臂同分 |
| `norm-fused-add-rmsnorm-l1` | ✅ 六件套 + 基线 | 三臂同分（但 rmsnorm 的 2读2写口径可能分出差别） |
| `moe-gating-l1` | ✅ 六件套 + 基线 | 三臂同分 |
| + 4 道新场景（attn/kv/linear/head） | 🔄 子 agent 进行中 | 三臂同分 |

**如果这一层真的 Δ≈0，那是有价值的结果**：说明"库清单"这层（B 臂）
在 L1 上就够用了，C 臂的判据层在 L1 上是冗余的。

### 第 2 层：L5 反事实题（**已就绪 6 道，但要换掉失效的那道**）

这是**唯一能区分 skill 与裸 agent 的题型**：正确答案是「这条路不通」。

| 题 | 状态 | 裸 agent 的行为 |
|---|---|---|
| `moe-asm-fmoe-l5` | ⚠️ **答案已被 A 臂推翻**（变成"有条件可用"） | 实测找出了正确配置 |
| `gemm-fp8-l5` | ✅ | 能测出来（同库同形状对照） |
| `moe-shared-expert-l5` | ✅ | 需要实测重叠度 |
| `attn-gqa-repeat-kv-l5` | ✅ | 可能猜对（"broadcast 别做"是常识） |
| `lin-hadamard-l5` | ✅ A 臂已跑（timeout，但找到 `dsa_fallback`） | 可能猜错 |
| `pipe-allreduce-l5` | ✅ | 可能猜对 |

**问题**：6 道里至少有 3 道裸 agent 能靠常识或实测答对。
真正能区分的是那些「看起来该做、实际不能做」的题。

### 第 3 层：新型题 —— **「给我们已有的结论，判断它对不对」**

这是我认为最该加的题型，因为它直接测 skill 的核心价值：

```
题面：我们历史上得出过一条结论「XXX」。
     请判断这条结论对不对，并给出依据。
```

- **裸 agent**：只能自己重测，或者凭直觉接受/拒绝
- **C 臂**：能查到这条结论的出处、当时的测量条件、后续是否被推翻
- **B 臂**：只有库清单，查不到

关键设计：**给出的是我们真实记录过的、有的对有的错的结论**，
包括那三次著名的错误（`in-house` 29 条 / 两个幽灵库 / 49.8 当峰值）。

这类题的判分：
- 判对 + 指出为什么 → 100
- 判对但说不出为什么 → 60
- 盲信我们的结论 → 0（对抗"权威偏见"）
- 找到我们记录里的反证 → 100 + 记入 corrections.log

## 三、执行顺序（按信息量排序）

```
第 0 步（已完成）
  ✅ doctor / verify / score / baseline 工具链
  ✅ 评分器区分度（定性 80 / 定量 100 / 方向错 0）
  ✅ 3 道 L1 题 + 6 道 L5 题

第 1 步（进行中）
  🔄 4 道新 L1 题（attn / kv / linear / head）—— 子 agent
  → 交付后跑三臂，预期 Δ≈0，用来**证伪**"L1 能测出 skill"

第 2 步（下一步，信息量最高）
  写 3 道「判断我们的结论对不对」题：
    - judge-inhouse-29：in-house 写了 29 条，实际库里有吗
    - judge-ghost-libs：hipBLASLt / TileKernels 存在吗
    - judge-49.8-peak：49.8 TF 是峰值还是某条实现的值
  这三道直接复现我们历史上的三次错误，裸 agent 极可能重蹈覆辙。

第 3 步
  跑 L5 六题三臂（已有题面，需要 GPU）
  → 第一份有意义的 Δ

第 4 步
  跑第 2 步的三道题
  → 如果 Δ 在这里出现，说明 skill 的价值在「判据」而非「库清单」
```

## 四、胜负线（跑之前定死，跑完不许改）

| 条件 | 结论 |
|---|---|
| L1 层 Δ_eff(C−A) < 20pt | **正常**：L1 本就不该有差别 |
| L5 层 Δ_eff(C−A) < 20pt | 砍文档：判据层没有传递到产出 |
| 第 3 层 Δ_eff(C−A) < 20pt | 砍文档：连"知道历史结论"都不值钱 |
| B ≈ C（差 < 10pt）在任何层 | 判据层无价值，只留库清单 |
| Δ_halluc(C−A) > 0 | **立刻停**，skill 在教模型编答案 |

**关键**：三层分开算。把 L1 的 Δ≈0 当成"实验失败"是错误的——
L1 的 Δ≈0 是**预期结果**，它证明 B 臂就够了。

---

## 五、当前已知的风险

1. **`moe-asm-fmoe-l5` 的答案已失效**——A 臂推翻了它。L5 层现在只有 5 道有效题，
   而且其中几道裸 agent 可能靠常识答对。
2. **`peak_achievable:bf16=279` 可能偏低 10%**（我实测 307）。
   影响所有 gemm 达成率，未改上游。
3. **sclk 读数不可信**——锁 1350 与 1200 测同一 kernel 结果完全一样。
   所以不能用它做频率折算。
4. **样本量**：每层 3–6 题 × 单次运行，统计上只能看方向，不能报 p 值。
   要出正式结论需要 8–10 题 × 3 次重复。
