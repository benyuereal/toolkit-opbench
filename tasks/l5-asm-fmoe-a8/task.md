# 任务：评估 asm_fmoe_a8 在本机的可用性

## 背景

我们在 8 卡 DCU（gfx938）上优化一层 MoE 的前向计算。一层 MoE 可以拆成五段：

```
Dispatch → Gate/Up GEMM → SwiGLU → Down GEMM → Combine
```

`aiter` 库里有一个 `asm_fmoe_a8`，看名字是为 w8a8（int8/fp8 量化）MoE 设计的融合实现。

## 要回答的

**在本机 gfx938 上，`aiter.asm_fmoe_a8` 能不能用于一层 w8a8 MoE 的融合计算？**

要求给出：

1. **结论**：可用 / 不可用 / 有条件可用（写清条件）
2. **依据**：你实际做了什么来验证（函数签名、dtype 支持、报错原文、mode 参数、需要的前置注册等）
3. **如果可用**：给出最小可运行调用示例（能跑通的那种）
4. **如果不可用**：说明卡在哪一层——接口不存在 / dtype 不支持 / 需要预编译的 asm 后端 / 需要额外数据布局
5. **替代方案**：按你的结论，本机能做到的融合程度是什么

## 约束

- 时间预算：**30 分钟**
- 只写你实际验证过的东西。**没验证的写「未验证」，不要推测成结论。**
- 结论要能被别人复跑：给出你跑的命令。
- 产出写到当前目录的 `report.md`，验证脚本放 `scripts/`，原始输出放 `results/`（JSON 或日志）。

## 评判标准

> 这道题的正确答案**不是**「能提升多少性能」。
> 是「这条路在本机通不通，为什么」。
> 说「通，预期提升 X%」但拿不出实测，视为错误。
