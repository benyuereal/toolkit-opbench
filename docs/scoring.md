# 评分规范

## 一、两种分，用途必须分开

| 分 | 公式 | 用途 | 为什么 |
|---|---|---|---|
| **ratio** | `T_b / T_k` | **主指标，比三臂高下** | 不饱和，能区分"快一点"和"快很多" |
| sol_like | `1/(1+(T_k-T_sol)/(T_b-T_sol))` | 报告里给人看 | 0.5 = 与基线持平，1 = 光速；**但在高分处饱和，不能拿来比高下** |

`T_b` = 基线（存档在 `baselines/<id>.json`），`T_k` = 被测实现，`T_sol` = 我们的 roofline 地板（用 `constants.yaml` + `bench/hw/constants.py` 算）。

**两条铁律**

1. 峰值只引用 constants 的 id（`peak_nominal` / `peak_achievable` / `impl_measured` 三类），**不许在代码里写字面量**。分母已经错过两次：540 无来源（空间估大 10.9×）、49.8 当峰值（估小 10.9×）。
2. 跨形状一律报 **几何平均**，不报单点。单点可以挑好看的。

## 二、judgment 类判分

| 情形 | 分 |
|---|---|
| 结论正确 + 有实测证据 + 说清机制 | **100** |
| 结论正确但证据不足 | 60 |
| 明确说"未验证 / 不知道" | 20（诚实，给分） |
| 结论错误，或编造证据 | **0**，并计入幻觉数 |

L5 的判据是"这条路通不通"。说"能优化 X%"但拿不出实测 = 编造。

## 三、四个治理指标

| 指标 | 定义 | 目标 |
|---|---|---|
| **有效结论率** | 有可复跑数字 + 复跑方法 的题数 / 总题数 | 越高越好 |
| **正确率** | 通过 public + holdout + 压力数值 的题数 / 总题数 | 100% |
| **校准度** | \|宣称达成率 − 实测达成率\| | ≤ 10pt |
| **幻觉率** | 编造的 `import_path` / 库名 / 数字 条数 / 总声明数 | **越低越好，且不得高于 A 臂** |

校准度是 49.8 那次事故的产物：它宣称"已到顶"，实际有 11 倍空间。

## 四、三臂 Δ

```
Δ_eff    = C.有效结论率 − A.有效结论率
Δ_halluc = C.幻觉率 − A.幻觉率        # 期望 ≤ 0
Δ_calib  = |C.宣称 − C.实测|          # 越小越好
```

**胜负线（跑前定死，跑完不许改）**

| 条件 | 结论 |
|---|---|
| `Δ_eff < 20pt` | 砍文档，不是加文档 |
| `B 与 C 差 < 10pt` | 判据层无价值，只留库清单 |
| `Δ_halluc > 0` | 立刻停，skill 在教模型编答案 |

## 五、防作弊（任一命中即该单元作废）

| 检查 | 判法 |
|---|---|
| 题面被改 | `task.md` 哈希与评测前不一致 |
| 计时被劫持 | `torch.cuda.Event.elapsed_time` 被 patch |
| 后台线程 | 线程数在评测前后不一致 |
| lazy 输出 | 返回值是未计算的 proxy tensor |
| 评测函数被替换 | 关键函数的 `id()` 快照对不上 |
| 小形状冒充大形状 | `claims.shape` 与实际运行 shape 不一致 |
| 只报最好一次 | 只给 min，没给 median + MAD |
| A 臂偷看 skill | 命中泄漏指纹表 |
