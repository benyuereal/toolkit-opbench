# 任务：MoE 五段融合的边界在哪

## 背景

我们在 8 卡 DCU（gfx938）上优化 MoE 层的前向。一层 MoE 可以拆成五段：

```
Dispatch → Gate/Up GEMM → SwiGLU → Down GEMM → Combine
```

现在的实现是五段分开跑。团队想融合，但"融合"不是一个二选一——
可以只融合相邻两段、融合三段、或者全融合。每多融一段就少一次 launch，
但 kernel 更复杂、寄存器压力更大、可调参数更少。

**问题是：什么条件下该融合，什么条件下该保持拆分？**

## 要回答的

**给出一个可执行的判据（拐点或规则），而不是一个结论。**

具体要给出：

1. **判据**：用什么量来判断（例如每专家平均 token 数、M 的大小、E 的大小），
   阈值大概在哪
2. **依据**：你实测了什么、怎么测的
3. **两种情况**：在阈值两侧分别应该怎么拆/融，各自理由
4. **反例**：什么情况下这条规则不成立
5. **复跑**：给出命令与脚本位置

## 约束

- 时间预算：**45 分钟**
- 只写你实际验证过的东西。**没验证的写「未验证」，不要推测成结论。**
- 计时必须用 GPU event（`torch.cuda.Event`），**不许用 wall clock**。
- 产出写到当前目录的 `report.md`，验证脚本放 `scripts/`，原始输出放 `results/`。

## 评判标准

> 这道题**不接受"融合更快"这种结论**，即使它是对的。
> 要的是「在 X 条件下融合优于拆分，X 的阈值大约是多少」——
> 一个后续工程师能直接拿去用的判据。
>
> 只给方向不给阈值 = 60 分。给了一个没实测支撑的阈值 = 0 分（编造）。
