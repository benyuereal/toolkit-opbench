# 参考答案（不给 agent 看）

## 当前已知结论（截至 2026-11-23）

**流量是 2 读 2 写，不是 2 读 1 写。** M=8192, H=4096 → **268 MB**。

依据：`lightop.fused_add_rms_norm(x, residual, weight, variance_epsilon)`
是**原地改写**型，实测：
- 返回值的 `data_ptr()` 分别等于输入的 `x` 与 `residual`
- 调用后 `x` 与 `residual` 的内容都被改

所以流量 = 读 `x` + 读 `residual`（2 读）+ 写 `out` + 写 `residual_out`（2 写）
= 4 × M×H×2B。**按 1 份输出算（201MB）是比了不同的活。**

## 参考数值（业主实测，仅供对照，不许抄进 baseline）

同一台 BW1100 gfx938，bf16，等语义 2读2写 268MB，event 隔离，交替 7 轮：

| 实现 | 中位 | MAD | 带宽 | 达 add 上限 |
|---|---|---|---|---|
| tilelang inplace t512 | 204.5 µs | ±0.8 | 1313 GB/s | 81.8% |
| lightop 原地 | 211.2 µs | ±0.6 | 1271 GB/s | 79.2% |
| triton inplace w1 | 212.3 µs | ±0.6 | 1264 GB/s | 78.8% |
| elementwise add（上限参照） | 125.4 µs | — | 1605 GB/s | 100% |

分母口径：`peak_achievable:copy` = 1350 GB/s（`memory.stream_copy_peak`，
本机 copy(R+W) 实测）。**不是** `spec_bandwidth` 的 1100（型号标称，不可复跑）。
用 1100 当分母会把 79% 算成 97%，结论从"还有空间"变成"已经打满"。

## 合格的回答长什么样

- 落到具体实现，写明签名与版本
- 明确说流量是 **2读2写**，并给出依据（原地改写 / 两个输出都要落盘）
- 分母用 `stream_copy_peak` 1350，并说明为什么不用标称值
- 达成率落在 ~75–85%
- 注意到原地改写每轮要恢复输入
- 至少两个 M 档位
