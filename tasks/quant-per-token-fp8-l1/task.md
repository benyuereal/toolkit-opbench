# 任务：per-token FP8 量化这一段，到底值不值得动

## 背景

我们在 8 卡 DCU（gfx938，Hygon BW1100）上跑 GLM 的 W8A8 推理。线性层的
**激活**在送进 FP8 GEMM 之前要先量化成 `float8_e4m3`。用的是 **per-token**
方案：每个 token（每行）一个独立的 scale。

为什么不能 per-tensor：一个 batch 里不同 token 的激活动态范围能差几个数量级。
共用一个 scale 时，最大值那个 token 定死了 scale，其余 token 全部塌进很小的
码值区间，精度损失不可接受。

这一段不做矩阵乘：读一遍 bf16、写一遍 fp8、再写 M 个 scale，没有计算。
它夹在每个线性层前面，每层都要跑一次。

团队要确认：**这一段现在值不值得继续投入？如果值得，该动的是哪一层？**

## 算子定义

```
输入
  x[M, H]        bfloat16

输出
  q[M, H]        float8_e4m3
  scale[M, 1]    float32
```

量化规则（**这是正确性定义，逐条对齐**）：

1. **scale 是 per-token**：沿**最后一维**（H）归约，第 i 行一个 scale。
   `scale` 的形状是 `[M, 1]`、dtype `float32`。
   `scale[i] = max_j |x[i, j]| / 448.0`
2. **quant_max = 448.0**（`float8_e4m3` 的最大规格化值）。
3. `q[i, j]` = `x[i, j] / scale[i]` 再转成 `float8_e4m3`（硬件舍入，
   round-to-nearest-even）。**不额外做 clamp**：`|x[i,j]| ≤ scale[i]*448`
   恒成立，转换本身不会溢出。
4. **全零行**：`max_j |x[i,j]| = 0` 时 `scale[i]` 会是 0（除零）。约定
   `scale[i] = 1.0`、`q` 该行全 0。本题 workload 不含全零行，但你的实现
   不该因此产生 NaN/Inf。
5. 输入用 `random` 生成，元素近似 N(0, 1)。

`H = 4096` 固定；`M` 是变量，会出现多个档位。

| 张量 | 形状 | dtype |
|---|---|---|
| `x` | `[M, 4096]` | bfloat16 |
| `q` | `[M, 4096]` | float8_e4m3 |
| `scale` | `[M, 1]` | float32 |

## 正确性判定（硬门槛）

量化是**有损**的，所以不比 `q` 的码值，也不比 `q` 逐元素。

判定看两件事：

**(a) `scale` 必须与定义一致**：`scale[i]` 与 `max_j|x[i,j]| / 448.0`
在相对误差 **1e-4** 内一致。这条是量化契约——下游 GEMM 拿它反量化，
它错了整个结果就错。

**(b) 反量化后与原始输入比**：
```
d       = q.float() * scale
rel_l2  = ||d - x|| / ||x||            ≤ 0.05
逐元素    |d - x| / max_j|x[i,j]|      ≤ 0.10
```
用**行最大值归一**而不是绝对 atol：这样尺度无关（输入整体乘 1e4 后
绝对误差会跟着涨，但占比不变）。

**这两条抓什么**：per-tensor 而不是 per-token（会让各行 scale 全同）、
quant_max 写错、scale 存成 bf16、输出没真做量化（全 0 或原样拷贝）、
形状/dtype 不对、NaN/Inf。
**不抓**什么：舍入方向（round-to-nearest-even 与截断的差异远小于上面的阈值，
两者都算合理实现）。

## 要回答的

**这一段现在值不值得继续优化？如果值得，瓶颈在哪一层？**

具体要给出：

1. **落到了哪个实现**：`库.函数`、版本、完整调用签名。自己写也行。
2. **实测耗时**：测量口径下发的每个 `M` 档都要有数字。
3. **有效流量**：这一段实际读写多少字节，怎么算的。
4. **地板对比**：按你算的流量，理论上要多久？实测是它的几倍？分母取自哪里？
5. **归因**：把实测耗时拆开看——它和张量大小是什么关系？
   这个关系说明了瓶颈在哪？给出数字，不要只给结论。
6. **结论**：该往哪一层投入？给出你实测数支撑的判断。
7. **复跑**：给出命令与脚本位置。
