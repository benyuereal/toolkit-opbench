# 算子分类与覆盖矩阵

## 五层（task 的 `tier` 字段）

| tier | 考什么 | 判据形态 | 预算 |
|---|---|---|---|
| L1 | atlas 有卡且已有实测 → 知识层能否直接用上 | 能否落到 `库.函数` 并跑出可复跑数字 | 1800s |
| L2 | atlas 没有或只有 draft → 迁移 | 允许"查不到"，但要说清查了什么 | 1800s |
| L3 | 融合/拆分、吸收/非吸收、重叠/串行 | **给拐点或规则**，不是给结论 | 2700s |
| L4 | 真实仓库改一处，不能回归 | 端到端指标 + 无回归 | 7200s |
| L5 | 正确答案是「不通 / 别做」 | 「不通 + 机制」满分；「能优化 X%」= 0 | 600s |

## 命名规范

```
tasks/<family>-<op>-<tier>/
  task.md      题面（三臂逐字相同）
  expect.md    参考答案（不给 agent 看）
  check.py     机检脚本（可选）
```

例：`tasks/moe-asm-fmoe-l5/`、`tasks/gemm-bf16-l1/`

## 为什么 L5 要单独成一族

历史上我们编过三次结论：
1. `in-house` 写了 29 条（明明库里有）
2. 两个幽灵库：`hipBLASLt` / `TileKernels`
3. 把 aiter 实测 49.8 TF 当成 fp8 峰值（差 10.9×）

**这三次都不是"不够聪明"，是"不敢说没有"。** 所以 L5 单独成套，先用最便宜的题把这个问题暴露出来。
