# 评测报告模板

> 复制本文件到 `reports/YYYY-MM-DD-<suite>-<commit>.md` 后填写。
> **结论先行**：第一节的三行必须能独立看懂，不依赖下文。

---

## 一、结论（三行，先说结果）

| 项 | 值 |
|---|---|
| 判定 | `C 优于 A` / `无显著差别` / `A 优于 C` / `不成立（门槛未过）` |
| 主指标 | 有效结论率 &nbsp;A `__%` → B `__%` → C `__%`（Δ_eff = `__` pt） |
| 是否继续投 | `继续` / `砍文档` / `只留库清单` / `立刻停` |

一句话理由：

> （例如：C 的有效结论率高出 27pt，且幻觉率未上升；代价是 2.4× token。）

---

## 二、门槛检查（**先过门槛，再比主指标**）

任一项不过，判定直接为「不成立」，不再看 Δ_eff。

| 门槛 | A | B | C | 通过条件 |
|---|---|---|---|---|
| 正确率（public + holdout + 压力数值） | | | | C ≥ A |
| 幻觉率（编造的函数/库/行号 ÷ 总声明） | | | | C ≤ A |
| 校准度（\|宣称 − 实测\| ≤ 10pt 的比例） | | | | C ≥ A |
| 作废率（题面被改 / 计时被劫持 / 重跑对不上） | | | | C ≤ A |

> 门槛的定义见 `docs/scoring.md`。幻觉率由 `bench/check/hallucination.py` 机检，
> 不接受人工判断；每一条都要能指到具体文本位置。

## 五、失败与异常（这一节往往比结论有用）

| 现象 | 哪一臂 | 判定 | 原因 |
|---|---|---|---|
| | | 作废 / 0 分 / 记幻觉 | |

必查三类：

1. **A 臂是否读到 skill**（隔离失效）——查 `runs/arm-a/*/artifacts` 有无泄漏指纹
2. **C 臂是否只是抄了 skill 里的结论**——查它有没有引用 `expect.md` 不存在的信息
3. **是否有题面被改 / 计时被劫持** —— `bench/check/integrity.py` 输出

## 六、可复现

```bash
git -C /workspace/toolkit-opbench rev-parse HEAD    # 本报告对应的被测版本
git -C /workspace/toolkit-skills rev-parse HEAD     # skill 版本（C 臂）
python3 -m harness.doctor                            # 环境体检快照
python3 -m harness.run --suite <suite> --arm <a|b|c>
python3 -m harness.collect --runs runs --out reports/
```

环境快照（doctor 输出）附在附录，**必须包含每张卡的 sclk 与库版本**——否则数字无法复跑。

---

## 七、限制声明（不写这一节，报告不可信）

按实际情况勾掉不适用的：

- [ ] 网络未隔离：三臂都可联网，可能自行搜到答案
- [ ] 样本量 < 10，结论仅供参考方向
- [ ] 同一题只跑了 1 次（未取中位）
- [ ] 分母为标称峰值而非实测（见 `bench/hw/constants.py` 的常量类型）
- [ ] 未做 holdout 形状与压力数值检查
- [ ] GPU 与其他任务共享，时钟档位可能波动
