# 任务：MoE 专家输出求和的带宽达成率

## 背景

我们在 8 卡 DCU（gfx938，Hygon BW1100）上优化 MoE 推理。一层 MoE 里，每个
token 会被 K 个专家各算一遍，最后要把这 K 份输出**加权求和**回该 token。

权重已经在外层乘进输入了，所以这一段只做**求和**：

```
out[m, :] = Σ_{k=0}^{K-1} expert_out[m, k, :]
```

它夹在 grouped GEMM 和下一层的投影之间，每层都要跑一次。

## 算子定义

```
输入  expert_out[M, K, H]      # K 个专家各自的输出
输出  out[M, H]                # 沿 K 轴求和

  K = 8, H = 2048 固定
```

| 张量 | 形状 | dtype |
|---|---|---|
| `expert_out` | `[M, 8, 2048]` | bf16 |
| `out` | `[M, 2048]` | bf16 |

`M` 是变量，会出现多个档位。

**注意求和轴**：沿第 1 维（K 轴）求和，不是最后的 H 轴。

## 正确性判定（硬门槛）

**输入输出对得上就算正确，不管用什么实现。**

- 判据是**相对 L2 误差** + 逐元素绝对上界，不是逐元素相对误差。
  原因：bf16 累加 K=8 份会出现**抵消**——8 个值的和恰好接近 0 时，
  绝对误差很小但相对误差会爆表（实测 max rel 达 3.5e6）。
  逐元素相对误差在这种元素上永远不可能过，那是判据不适配，不是实现错。
- 累加精度：参考实现用 fp32 中间量。bf16 直接累加会有几 ULP 的差异，属正常。

## 要回答的

**在本机跑这一段，带宽达成率是多少？还有多少空间？**

具体要给出：

1. **落到了哪个实现**：`库.函数`、版本、**完整调用签名**
2. **实测耗时**：题面给出的每个 M 档都要有数字
3. **有效流量**：这一段实际读写多少字节，怎么算的
4. **达成率**：分母取自哪里、为什么可信
5. **结论**：还有多少空间、下一步该动哪里（或者"已经到顶，别动"）
6. **复跑**：给出命令与脚本位置

## 约束

- **时间预算：30 分钟**
- 只写你实际验证过的东西。**没验证的写「未验证」，不要推测成结论。**
- 计时必须用 GPU event（`torch.cuda.Event`），**不许用 wall clock**。
- 每轮计时前要处理 L2 缓存（本机 L2 = 8 MB）。
- 产出写到当前目录的 `report.md`，脚本放 `scripts/`，原始输出放 `results/`。

## 评判标准

> 这道题的流量口径很直接，但要看清**读写比**——它决定了该用哪个带宽档位当分母。
> 分母选错，达成率就错，结论会整个反过来。
>
> 另外：只报一个形状、拿最好看的那个说话，视为不足以支撑结论。
